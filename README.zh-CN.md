# rst-window-audit

**CITES 2026 年三年锐增窗口的检测层审计**：可复现代码与结果包。

本研究只问一个范围明确的问题：当锐增判据只检查焦点年份时，哪些有记录支持的激增落在检测层之外？随后在固定候选名单上比较“延长回看窗口”和“降低阈值”两种做法。仓库包含完整分析链（面板 → 标签 → 特征 → 滚动排序 → 审计 → 敏感性 → 图件 → 数字闸门）、冻结的汇总表、论文五张图，以及逐个头条数字的机器校验。

论文正在评审中。**为双盲评审，仓库不包含作者信息**；原始 CITES 贸易记录**不再分发**，官方下载地址与建库步骤见 [`data/README.md`](data/README.md)。

## 快速开始（无需下载原始数据）

```bash
python -m pip install -e ".[dev]"
rst-audit reproduce
```

`reproduce` 只用仓库内已有的汇总表重画五张图，并重跑全部数字校验，不需要 CITES 数据库。成功时以 `all N checks passed` 结束，并把结果写入 `results/checks/checks.csv`。

运行测试（不联网、不依赖原始数据）：

```bash
pytest
```

## 完整流水线（从 CITES 官方导出开始）

1. 从 <https://trade.cites.org/> 下载 CITES 贸易数据库 2026.1 版批量导出；下载与许可说明见 [`data/README.md`](data/README.md)。
2. 转成流水线使用的 DuckDB 表 `trade`：

   ```bash
   python scripts/prepare_cites_db.py --csv /path/to/cites_trade.csv --out data/cites.duckdb
   ```

3. 运行全链：

   ```bash
   CITES_DB=data/cites.duckdb rst-audit pipeline
   ```

   也可分阶段运行：

   ```bash
   rst-audit panel       # 出口国 × 分类单元 × 年份面板（2000–2024）
   rst-audit labels      # 锐增状态、一年标签与三年标签
   rst-audit features    # 60 个剔除规则特征的特征，按标签年逐年输出
   rst-audit models      # 滚动起点 LightGBM，五个测试年，种子 0–2
   rst-audit audit       # 分歧集、案例核查、固定名单比较
   rst-audit sensitivity # 阈值、模型族、进口侧与滞后字段检验
   rst-audit figures
   rst-audit checks
   ```

各阶段幂等：已有产物默认复用，加 `--force` 才重建。路径由环境变量 `RST_DATA_DIR`、`RST_OUT_DIR`、`RST_RES_DIR`、`RST_FIG_DIR`、`RST_LOG_DIR` 与 `CITES_DB` 控制。

## 一页读懂方法

**单元与口径。** 单元是“出口国 × 分类单元”。主口径为出口方申报的直接贸易，只计 `Number of specimens` 单位，`Origin` 为空或等于出口国的记录（出口侧惯例）。面板覆盖 2000–2024 年，共 301,914 个单元—年份；2018–2022 测试期涉及 32,062 个出口国—分类单元组合。

**锐增判据。** 单元在 *t* 年触发，当且仅当

```
V(t) > 4 × mean(V(t−5 … t−1))   且   mean(V(t−5 … t−1)) ≥ 100。
```

全球变体还要求物种总量通过同一检验、且该单元占世界出口量至少 10%。一年标签看 *T* 年；三年标签看 *T*、*T−1*、*T−2* 中任一年。

**独立排序。** 为避免“用规则审计规则”，模型训练所用特征集剔除了锐增标记、规则比值、五年均值/五年总量、濒危状态标记及其近似代理，保留 60 个特征（贸易历史、网络位置、贸易形态、分类学、记录质量）。LightGBM 采用滚动起点：每个测试年只用更早年份训练、当年评分。分数只用于产生候选，审计只依赖榜单前列，不依赖总体预测性能。

**分歧集。** 模型排名靠前、但一年规则未触发的单元。报告三种选取规则：合并前 50 名、逐年前 10 名（五年合计 50 个）、不过滤前 50 名。

**案例核查。** 每个分歧案例都从原始面板重算。核查支持窗口为 *T* 前五年并剔除触发年；窗口内至少两个正记录年份、且最近触发年的记录数不低于支持年份记录数中位数的一半，才记为“核查通过”。只有一个支持年份的案例进入观察名单。该判定只陈述内部记录一致性，不构成对贸易可持续性的确认。

**固定名单比较。** 固定同一模型前 100 名候选，把各种规则（一/二/三年窗；2×/3×/4×/5× 阈值）施加于同一名单。这样回答的是“固定审查预算下有多少案例进入名单”，而不是“全池有多少单元触发”。

## 头条结果（均有机器校验）

- 34 个合并分歧案例全部在 *T−1* 触发，其中 10 个同时也在 *T−2* 触发，没有一个在 *T* 触发。盲区的主因是激增未在焦点年重演，而不是“差一点到阈值”（三种选取规则下接近阈值案例均为 0）。
- 34 个案例中 18 个有多年记录支持并通过核查，16 个只有单年支持、进入观察名单。
- 固定前 100 名名单下，一年规则每年标出 34.2 个单元；三年窗标出 60.4 个，新增 15.0 个核查通过案例；3× 阈值只新增 6.2 个、其中 2.6 个核查通过。三年窗新增的核查通过案例约为阈值调整的 **5.8 倍**。
- 两年窗已贡献名单层面几乎全部增益（14.8 个核查通过）；第三年的主要价值是覆盖完整候选总体：3,098 个三年阳性单元中有 879 个（28.4%）只在 *T−2* 触发，位于榜单前列之外。
- 盲区集中于危地马拉与植物，但不为其独有：剔除危地马拉后仍余 30 个案例；再剔除 2017 年报告足迹至少翻倍的出口国后仍余 28 个。
- 34 个案例中 29 个能配对到进口方申报记录，但其中 28 个的原产国字段完全缺失，数量比值中位数为 0.15。进口记录可以配对，却无法复核激增幅度；这是数据边界，不是检索失败。

## 三个设计要点

**为什么剔除规则特征？** 能接触 `V/M` 或五年均值的模型可以复现规则，它产生的分歧大多只是阈值附近的重复识别，不能作为时间覆盖缺口的独立证据。论文同时报告全特征对照（26 个案例，其中 4 个接近阈值），但审计结论采用剔除规则特征的排序。

**为什么固定名单？** 一条规则可以在全池标出很多单元，却完全不改变一个每年只能审查 100 个候选的团队的工作量。固定模型前 100 名，才能隔离规则对“实际会被审查的名单”的影响。

**为什么叫审计而不是预测？** 模型只是候选生成器，不是因果模型。“核查通过”指记录内部一致，不等于确认非法或不可持续的贸易。论文对单次数据库快照的边界有明确交代。

## 可复现契约

`results/checks/expected.json` 保存了 66 项由仓库内汇总表算出的量：案例数、触发年分布、名单各方案、集中度、进口匹配、滞后字段、模型族范围。`rst-audit checks` 重新计算并逐项比对，任一不符即以非零状态退出（容差 `5e-4`）。该文件是契约而非便利：表格一变，闸门就红，直到论文数字与期望值被有意地重新对齐。

流水线已与论文所用上游冻结产物逐项对齐：

- 标签：421,354 行、4,998 个一年阳性、11,759 个三年阳性；
- `v_cnt`、`m5`、`si_c`、`si3_c`、`si_g_u`、`y_B`、`y_B3`、`active5` 与上游标签在机器精度内相等；
- 每个模型矩阵（`feat_T*.parquet`，71 列）与上游文件逐元素相等；
- 五个测试年的 seed-0 LightGBM 得分与论文所用得分完全一致（最大 |Δ| = 0，top-100 名单相同），因此固定候选名单、案例表及全部下游数字都可重新生成；
- 模型族表在钉死 XGBoost 线程数（`config.XGB_THREADS`）后精确复现——直方图法在不同线程数下会建出不同的树（实测 4 线程与 20 线程的单元得分最大相差 0.29），随机森林则与线程数无关；
- `rst-audit reproduce` 通过全部 66 项校验，测试套件全部通过。
